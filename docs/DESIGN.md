> 状态：当前 `main` 的实现说明
>
> 版本来源：`Cargo.toml`；发布状态来源：GitHub Releases；验证结果来源：GitHub Actions 和 `docs/release/results/`
>
> 本文不固定提交号、测试数量、二进制大小或性能测量值，避免把易变信息复制成第二份事实源。

## 1. 目的

rshot 是一个 Windows 常驻截图工具。一次截图操作从全局热键开始，经过屏幕捕获、区域选择和标注，最终复制图片、识别文字、生成置顶贴图或取消。

设计目标：

- 截图失败后仍能继续使用热键，不遗留遮罩窗口或旧会话。
- 复制、OCR 和贴图使用同一张冻结图和同一套选区语义。
- 已有贴图不进入新的截图，但只在读取桌面像素期间短暂隐藏。
- 发布到剪贴板的图片可被位图消费者和文件消费者使用。
- OCR 完全离线，模型失败时可回退到 Windows OCR。
- 诊断只记录稳定错误码，不记录用户内容。

不属于当前范围：

- macOS、Linux、移动端。
- 滚动长截图、录屏、延时截图和跨显示器联合框选。
- 截图历史、云同步、账户和服务端。
- 标注对象选择、图层、移动和完整撤销树。
- 后台 OCR 服务和运行中自动升级。

领域术语以 [CONTEXT.md](CONTEXT.md) 为准。

## 2. 核心不变量

1. 同一时刻最多存在一个活动截图会话。
2. 冻结图始终是没有标注、没有 rshot 贴图的原始屏幕像素。
3. 捕获尝试全部成功后才提交截图会话；失败路径释放本次资源。
4. 贴图隐藏租约只覆盖桌面像素读取，成功、失败或租约析构都会恢复贴图。
5. 选区、窗口锁定、预览、OCR 和最终输出使用同一物理像素坐标系。
6. 重新选择保留冻结图，清除旧选区和旧标注，不重新捕获屏幕。
7. 没有选区且没有标注时，截图输出借用冻结图；需要裁剪或标注时才生成新图。
8. 图片复制至少发布一种格式且剪贴板正常关闭后，才结束截图会话。
9. OCR 只读取冻结图或其选区，不读取标注层。
10. OCR worker 完成、失败或超时后退出；父进程异常结束时由 Job Object 回收。
11. 最多保留 8 张贴图；第 9 张失败不能破坏当前会话或已有贴图。
12. 关闭一张贴图只影响对应 `WindowId`。
13. 失败诊断只写时间、版本、事件和 `RSH-*` 错误码。
14. 没有活动会话和贴图时，不保留截图像素，也不加载 OCR 模型。

## 3. 运行结构

rshot 发布为一个 `rshot.exe`，但有两个运行角色：

| 角色 | 生命周期 | 职责 |
| --- | --- | --- |
| 常驻应用 | 用户启动至退出 | 托盘、全局热键、截图会话、贴图、剪贴板和 Windows 事件循环 |
| OCR worker | 每次高精度 OCR 临时创建 | 加载嵌入模型和 ONNX Runtime、识别一张有界图片、返回 UTF-8 后退出 |

主进程不直接加载 ONNX Runtime。worker 通过 stdin 接收有界 RGBA 请求，通过 stdout 返回有界结果；stderr 也有读取上限。worker 加入 kill-on-close Job Object，避免父进程异常退出后残留。

当前 OCR 编排仍由主事件线程同步等待 worker 和 Windows OCR 回退，因此 OCR 期间界面可能无响应。这是当前最重要的架构限制，而不是已解决能力。

## 4. 模块边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `app` | 常驻状态和跨模块用例编排 | 解释截图窗口的细粒度交互 |
| `capture_operation` | 捕获尝试、截图会话、窗口事件和会话资源所有权 | 剪贴板事务、OCR 推理和贴图集合 |
| `capture_operation::attempt` | 光标/显示器匹配、隐藏贴图、捕获冻结图和创建遮罩资源 | 选择和编辑 |
| `capture_operation::interaction` | 选择、编辑、工具、IME、revision 和高层命令 | Windows 窗口创建和业务副作用 |
| `output` | 根据冻结图、选区和标注生成最终 RGBA | 剪贴板和窗口生命周期 |
| `clipboard` | 准备格式、执行 Win32 剪贴板事务、报告实际格式和确定性 | 截图输出组合 |
| `temp_artifact` | 创建、保护、保留和清理剪贴板临时 PNG | 任意用户临时文件 |
| `ocr` | 模型优先、Windows 回退、结果和失败分类 | 截图会话生命周期 |
| `ocr::worker` | 进程协议、运行时提取、模型推理、超时和回收 | 用户提示和剪贴板 |
| `pinned` | 最多 8 张贴图的创建、显示、移动、关闭和捕获可见性租约 | 截图选择和标注 |
| `render` | 遮罩、选区、工具栏、标注预览和贴图像素绘制 | 状态迁移 |
| `windows_adapter` | 通用 Win32/WinRT 边界和 unsafe 封装 | 产品流程 |
| `diagnostics` | 稳定错误码日志和隐私安全导出 | 原始错误详情持久化 |

`App` 只长期拥有配置派生状态、热键 ID、一个可选 `CaptureOperation`、`PinCollection`、剪贴板发布器和临时产物生命周期。截图的冻结图、窗口、Surface、选区和标注由 `CaptureOperation` 聚合。

## 5. 截图状态

### 5.1 捕获尝试

顺序：

1. 读取物理光标位置。
2. 找到 xcap 捕获显示器。
3. 匹配 winit 遮罩显示器及物理原点。
4. 获取贴图隐藏租约。
5. 读取冻结图。
6. 立即完成租约并恢复贴图。
7. 枚举可锁定窗口。
8. 创建遮罩 Window、图形 Context 和 Surface。
9. 全部成功后提交截图会话。

步骤 1～8 任一失败都不会留下活动截图会话。贴图租约通过 RAII 覆盖提前返回。

### 5.2 截图会话

| 阶段 | 主要状态 | 允许动作 |
| --- | --- | --- |
| Selecting | 冻结图、候选窗口或手动选框 | 确定选区、取消、直接贴图 |
| Editing | 冻结图、有效选区、标注、工具和颜色 | 标注、撤销、复制、OCR、贴图、重新选择、取消 |

原始 `WindowEvent` 由交互模块解释为高层结果。`App` 只执行复制、OCR、贴图、关闭或故障恢复等副作用。

重新选择只重置交互状态；冻结图保持不变。

## 6. 输出与剪贴板

`ScreenshotOutput` 是复制和贴图共同消费的输出边界：

- 无选区、无标注：借用冻结图。
- 有选区：按规范化矩形裁剪。
- 有标注：按创建顺序合成画笔、直线、矩形和文字。
- 文字栅格化失败：整个输出失败，不交付缺少文字的图片。

图片剪贴板尝试发布：

- `CF_DIB`：供位图消费者直接读取。
- `CF_HDROP`：指向唯一的受管 PNG，供资源管理器和上传控件读取。

发布事务依次执行 `OpenClipboard`、`EmptyClipboard`、多个 `SetClipboardData` 和 `CloseClipboard`。打开阶段有限重试；其他阶段不盲目重试。结果包含：

- 实际成功格式。
- 失败阶段。
- 事务是确定、未改变还是不确定。

临时 PNG 只有在文件格式成功交给系统后才保留。清理只处理命名和目录都符合白名单、超过保留期且未被当前剪贴板引用的文件。

## 7. OCR

默认路径使用嵌入的 PP-OCRv6 检测/识别模型和 ONNX Runtime CPU worker。输入有最大尺寸和总像素预算；协议、stdout 和 stderr 都有大小限制。

结果顺序：

1. 高精度 worker 返回非空文字：使用该结果。
2. worker 无文字：以结构化原因回退 Windows OCR。
3. worker 不可用或失败：以结构化原因回退 Windows OCR。
4. Windows OCR 也失败：恢复原截图会话并提示稳定失败阶段。

OCR 后处理只依据识别区域坐标和原图像素证据恢复阅读顺序、项目符号、成对引号和混排空格，不根据句义猜写字符。

当前限制：

- 主事件线程同步等待 OCR。
- worker 有超时，Windows OCR 回退没有独立超时。
- 用户不能取消正在执行的 OCR。
- Windows 回退能力取决于系统语言包。

## 8. 贴图

每张贴图独立持有最终 RGBA、Window、Surface 和交互状态。贴图集合以 `WindowId` 路由事件。

- 左键拖动移动贴图。
- 左键双击、右键、`Esc` 或系统关闭事件关闭当前贴图。
- 双击需要两次短点击在时间和位置阈值内；发生拖动后清除未完成的双击序列。
- 新贴图先完成 Window、Surface 和图像准备，再插入集合并显示，避免第一次生成无反应。
- 捕获期间新提交的贴图在租约结束后统一显示。
- 单张贴图重绘失败只移除该贴图。

## 9. 失败与诊断

失败边界：

| 边界 | 失败后的状态 |
| --- | --- |
| 捕获尝试 | 无活动会话；贴图恢复；热键可重试 |
| 截图渲染 | 关闭故障会话；保留常驻进程和无关贴图 |
| 图片输出 | 保留同一会话、选区和标注供重试 |
| 剪贴板发布 | 根据事务结果保留会话；已交给系统的临时文件不提前删除 |
| OCR | 保留会话；记录最终失败阶段；允许重新操作 |
| 单张贴图 | 只关闭或移除对应贴图 |

稳定错误码域：

- `RSH-CAP-*`：捕获尝试。
- `RSH-OUT-*`：截图输出。
- `RSH-RND-*`：截图渲染。
- `RSH-CLP-*`：剪贴板发布。
- `RSH-OCR-*`：文字识别。
- `RSH-PIN-*`：贴图。

持久日志采用固定字段，不保存坐标、窗口标题、图片像素、OCR 文本、剪贴板内容、文件路径或原始系统错误。诊断导出重新解析并过滤日志，而不是原样复制。

## 10. Windows 边界与资源

- 进程启动时请求 Per-Monitor V2 DPI awareness，内部统一使用物理像素。
- `windows_adapter`、剪贴板和窗口适配器集中承载 Win32/WinRT unsafe 调用。
- Live Window 的 Surface 必须先于 Window 释放。
- OCR worker 的动态运行时按版本和内容摘要提取，不能覆盖其他版本目录。
- 主进程待命时不加载 OCR 模型。
- 每张贴图保留自己的 RGBA 和 Surface；数量上限避免无界增长。
- 事件循环仍有固定周期唤醒，常驻功耗尚未形成跨设备基线。

## 11. 配置与兼容性

配置由 `confy` 和 `serde(default)` 加载：

```yaml
hotkey: Alt+A
quit: Alt+D
diagnostics: true
```

新增字段必须有默认值。删除字段或改变字段语义需要显式迁移和相应版本策略。Release 不删除用户配置、诊断文件或未知临时文件。

## 12. 验证与发布

质量门禁的事实源是 [.github/workflows/quality.yml](../.github/workflows/quality.yml) 和 [RELEASE.md](RELEASE.md)。干净检出必须通过格式、严格 Clippy、测试、Release 构建和制品冒烟。

自动化覆盖包括：

- 截图会话状态和连续会话。
- 贴图集合、容量、隐藏租约和关闭手势。
- 输出裁剪、标注和文字失败。
- 剪贴板编码、事务和临时产物生命周期。
- OCR 编排、协议、超时边界和版本化中英文样本。
- 隐私安全诊断导出。
- Release 可执行文件的 OCR、剪贴板和会话自测角色。

真实 DPI、多屏、IME、外部剪贴板消费者和升级/回退环境记录在 [Windows 回归矩阵](release/windows-regression-matrix.md)。未执行的交互项目必须标记为 `BLOCKED`，不能由无窗口自测替代。

## 13. 已知风险与优先级

### P0：正式发布前

- 完成或获得可接受的真实 Windows 交互回归证据。
- 为项目本身确定许可证；第三方声明不能替代项目许可证。
- 保持稳定版与通过完整矩阵的候选版来自同一提交。

### P1：下一阶段架构

- 把 OCR 从同步调用改为带会话 ID 的异步操作。
- 定义 OCR 完成、失败、超时、取消和旧结果丢弃协议。
- 为 Windows OCR 回退增加有界等待。
- 保证 OCR 期间贴图和事件循环保持可用。

### P2：维护性

- 继续缩小 `app/mod.rs`、`ocr/engine.rs` 和 `pinned/mod.rs` 的职责热点，但只在存在明确变化理由时拆分。
- 移除未使用依赖，降低 beta/RC 依赖升级风险。
- 测量待命轮询的 CPU、唤醒和笔记本功耗，再决定是否改为事件驱动唤醒。
